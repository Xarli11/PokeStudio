# PokeLab — Community Model

## Principle

**Community-informed, owner-led.**

Community feedback receives high weight. Final roadmap/product decisions remain with the project owner.

## Early channels

GitHub-first:

- Issues for actionable bugs/tasks,
- Discussions for ideas/Q&A/feedback,
- public roadmap,
- changelog,
- contributor recognition.

A Discord/community server can be introduced when there is enough activity to justify moderation overhead.

## Contributions

Repository may be public early, but broad external contributions should be actively invited only after the base architecture is stable and the contribution/license process is ready.

## Product UGC sequence

Prioritize:

1. shareable teams,
2. public teams,
3. likes/bookmarks,
4. forks with attribution lineage,
5. comments only when moderation is ready,
6. guides/creators later.

Do not build a generic social feed without evidence users need one.

## Moderation

Before public UGC at scale:

- report content,
- moderation states,
- ban/restrict users,
- audit moderator actions,
- define public community guidelines.
